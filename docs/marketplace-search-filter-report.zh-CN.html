01 / EVIDENCE

证据来源与可信边界

官方证据

IRONMACE 更新说明证明了随机词条下拉框、按物品名计算最大页、不可交易物品处理，以及随机词条规则会随赛季变化。

直接协议证据

固定版本的 MarketPlace.proto 直接暴露过滤器枚举、升降序、当前页/最大页，以及总价和堆叠数量的区分。

API 第一方证据

DarkerDB 是社区服务，但其官方文档与 live 响应是判断该 API 合约的第一手资料。本次使用固定合约 2026-08-03 验证。

不要过度推断：DarkerDB 和 DnDTools 都不是 IRONMACE 产品。协议能证明过滤器类别和分页字段，却不能自动证明当前游戏 UI 的精确布局、每个下拉框内部 OR/AND 语义或所有特殊物品行为。

仍需以后用只读抓包或当前游戏画面确认

  • 游戏内每页固定结果数
  • 每类过滤值的实际序列化字符串
  • 当前排序字段代码
  • 每个下拉框内的 OR/AND 行为
  • 服务端 min/max 是否全部含边界
  • 神器、制作、插槽和不可交易物品的全部特例
  • 当前 UI 控件顺序和精确布局
  • 当前 listability 完整规则

随机词条与数值范围

规则

  • 随机词条属于 secondary attributes。
  • 可出现的词条集合取决于具体物品。
  • 基础主属性不能再以相同随机词条重复出现。
  • 同一物品不能重复出现同一个 modifier。
  • 词条族互斥还会造成更多自然不可能组合。

已确认的单位风险

Epic Arcane Garb 的 Price Check 显示 Magic Penetration 为 1.5–3.0%，Market 实际 roll 为 2.4%；Item Detail 却给出 15–30。

范围控件必须使用明确的统一单位。第一版优先采用 Price Check 的 available attributes；Item Detail 必须经夹具验证归一化后再使用。

堆叠、价格与自动上架边界

搜索结果

Market 行同时包含整单 price、单位价 price_per_unit 和数量 quantity。数量大于 1 时必须同时展示总价和单位价。

可交易与时效

列表资格会受 is_tradable、loot state 和当前游戏规则影响。当前观察到的 listing 期限为 7 天，但应随版本记录。

既定定价规则

最近 5 个可用成交 → 取单位价最低 3 个 → 算术平均；缺价不自动回退；堆叠先乘数量再调整；最后 half-up 到整金币。

03 / API

DarkerDB 端点与合约分析

Items

GET /v2/items 提供当前 patch 目录，支持 archetype、精确名、品质、物品/护甲/手持/武器/栏位类型、尺寸、价格/评分、职业、制作/神器和属性范围。分页使用不透明 cursor。

  • required_class=a|b 为并集；无职业限制的物品匹配所有职业。
  • archetypes=1 将不同品质变体折叠为物品族。
  • GET /v2/items/{id} 提供具体物品的主/次属性可能范围。
  • cursor 响应中的 total 应按“可选字段”处理。

Attributes / Classes

/v2/attributes 返回规范 ID、名称、描述、百分比标记和 primary/secondary 分组；/v2/classes 返回规范职业 ID 与本地化标签。

live 请求 limit=200，实际返回 limit=50、secondary 总数 51 并带 next cursor。客户端必须追随响应 cursor，不能假设文档上限被接受。

Market

/v2/market 支持单个 item ID/archetype、单品质、逗号并集 slot、价格/单位价/数量/时间范围、主次属性范围、listing/lifecycle/loot state，以及按时间、总价、单位价或 ID 排序。每页 1–50。

  • 多个属性过滤器在服务端是 AND。
  • 仅当 K=N 时才能安全推送全部属性规则。
  • 精确物品查询含 freshness；陈旧的空结果不代表市场确实为空。
  • 超过约 50,000 的 total 可能是估算。

Price Check

/v2/price-checks 对一个具体物品和指定 rolls 做估值，返回选择、可用属性范围、fair/low/high/quick-list、信心、active/30 天推断成交数，以及相似 listings/sales。

它不是批量搜索接口，也不进入 Marketplace Search 的默认结果流程。搜索结果来自 Market 批量 listings 与本地过滤；展开结果不调用 Price Check。该端点保留给静态范围验证或后续独立的自动上架定价流程。

live 检查发现的三个关键缺陷

多品质序列化错误

现有 adapter 用逗号连接多个 rarity；live 的 rarity=rare,epic 返回 0 行，而单独查询两者都有大量结果。必须拆分/解析为具体 ID，不能照搬 slot 的逗号并集。

Price Check schema drift

仓库 schema 要求 selection.attributes 是数组；固定合约的当前响应却是由 attribute slug 键控的对象。未修复前 live 校验可能直接失败。

百分比范围单位不一致

Item Detail 的 15–30 与 Price Check / Market 的 1.5–3.0 和 2.4 不在同一显示尺度。必须建立显式归一化规则并用夹具证明。

词条范围的精确行为

  • 空 min/max = 无边界；边界比较包含等号。
  • 支持小数和带符号的主属性。
  • 百分比显示 %，内部存统一数值。
  • NaN 或 min > max 就地报错，不能发请求。
  • 显示当前物品上下文的自然 roll 范围。
  • 多个物品范围不同：显示并集范围 +“因物品而异”。
  • 实际缺失、超范围、自然不可能都只让该规则为 false。
  • 任何一条 false 都不能错误地跳过或否决其他规则。

SearchSpec

以不可变、带版本的规范模型替换当前狭窄且未使用完整的 SearchQuery。字段包括 class IDs、family IDs、category/slot/type slugs、rarities、总价/单位价范围、attribute rules + K、active-only、sort、retrieval budget。locale 只影响显示，不改变过滤身份。

规范目录

  1. 加载缓存 facets/classes/attributes/items。
  2. 校验 API 版本、build、patch、ID、重复和分页完整性。
  3. 分别取 en / zh-Hans 后按 ID join。
  4. 按 family、rarity、class、type、slot 建索引。
  5. 按具体 item ID 建 possible-roll/range 索引。
  6. patch 变化时保留上一个已验证目录，直到替换完成。

三个 count 不能混

retrievedCount：成功解析但尚未去重的原始行。

evaluatedCount：去重后真正进入规则计算的候选。

matchCount：通过所有普通组与 K-of-N 的去重候选。

缓存、取消与 stale protection

对象策略关键保护
Facets / Classes / Attributes / Items按 patch/version 持久缓存；5 分钟或 build/patch 变化后 revalidate更新失败时保留旧的已验证目录并标 stale
Market pages按规范 query/page 内存缓存 15 秒stale-while-refresh 必须明确标注
Price Check按 item + normalized rolls + locale 内存缓存 15 秒仅按需，不为每行请求
本地过滤结果candidate fingerprint + rule fingerprint不可变候选快照
取消所有 client 方法接收 AbortSignal；新 Search 取消旧 pages/Price Check只有最新 monotonic generation + fingerprint 可发布
重试幂等 read 可在用户任务内按 Retry-After 对 429/5xx 重试一次自动上架 retry 规则完全独立

本地化与确定性排序

中英文

  • UI：en-US 与 zh-CN，CI 中 key 完全一致。
  • DarkerDB：en 与 zh-Hans。
  • 规范 ID/facet slug 是存储与查询身份。
  • 中文缺失回退英文，再缺失显示 ID。
  • 切语言只重渲染，不重新查询 Market。

最终排序

  1. 用户选择的价格基准与方向
  2. created time 降序
  3. canonical item ID 升序
  4. 数字/字符串 listing ID 升序

绝不依赖响应到达顺序或 JavaScript 对象迭代顺序。

09 / QUALITY

测试与夹具要求

合约测试

  • Items list/detail、Attributes、Classes、Facets、Market、Price Check 当前夹具。
  • Price Check selection.attributes object，并在合约允许时兼容旧 array。
  • Item Detail、Price Check、Market 百分比归一化。
  • rarity comma 回归；slot comma union。
  • cursor optional total、effective limit 小于请求值。
  • fresh/stale/missing freshness。
  • 401/403/429/5xx 与空结果严格区分。
  • 版本/build/patch/rate headers。

Query planner

  • 多名称 × 多品质解析为 concrete IDs。
  • 职业并集包含 unrestricted items。
  • 组间 AND、组内 OR。
  • K=N 下推全部；K<N 不下推非必需规则。
  • 无组合 fan-out；空目录解析不请求 Market。
  • 总预算、round-robin 公平性。
  • 每族 partial error 与聚合 completeness。
  • 跨族重复 listing 只评估一次。

本地过滤

  • 零启用规则直接通过。
  • min/max 含边界、小数百分比、带符号值。
  • 逐 item 的自然不可能 lookup。
  • 混合 item families 的不同 possible rolls。
  • possibility unknown 与 naturally impossible 分开。
  • disabled / duplicate rule 行为。
  • 响应到达顺序不影响最终排序。
  • retrieved/evaluated/matched 定义。

UI

  • 每个控件可标记且键盘可用。
  • 切语言保持选择身份。
  • Search 与 Apply locally 草稿状态。
  • 所有 initial/loading/load-more/empty/incomplete/stale/rate/auth/partial/fatal 状态。
  • count announcement、table/card breakpoints。
  • filter sheet focus、reset/remove/edit。
  • 页面不存在硬编码假结果。

10 / RESOLVED

已确认的 6 个产品决定

2026-09-01 已锁定
最终工作流：用户点击“搜索”后，Companion 从 DarkerDB Market 批量拉取严格候选，在本地完成高级筛选；用户根据结果自己去游戏 Marketplace UI 搜索和购买。Companion 不操作游戏市场，也不自动购买。
01多职业使用 OR

已决定：物品可被任意一个所选职业使用即通过，并包含无职业限制物品。

02名称选择物品族，品质独立

已决定：名称选择 Arcane Garb 这样的规范物品族；品质单独多选；内部解析为 concrete IDs。

03默认预算 20 请求 / 1,000 listing

已决定：每次显式搜索使用一批有界预算；“加载更多”再明确消耗下一批。

04批量 Market 数据 → 本地高级筛选
每个 Market API 请求拉回一个严格物品/品质/栏位/价格候选列表；Companion 合并、去重后，在本地完成职业、类别、高级类型和 K-of-N 等剩余筛选。

已决定：结果行不逐条调用 Price Check，展开结果也不触发额外估值请求。

05按单位价排序，同时显示总价

已决定：默认单位价升序 → 最新 → listing ID；每行同时明确显示单位价与整组总价。

06只有点击“搜索”才请求

已决定：编辑筛选、展开结果、切语言、切标签或窗口焦点变化都不发新的 Market 请求；可复用候选时允许“本地应用”。

不需要你做产品决策的问题

以下应通过代码或研究回答：游戏当前固定页大小、过滤器字符串序列化和组内逻辑、排序字段代码、Price Check object/array 兼容、百分比尺度、cursor total 与文档 limit 稳定性、各类特殊物品的精确 listability。

11 / DELIVERY

推荐实施阶段与验收标准

M1 · 当前合约与规范目录

工作：新增 Facets/Classes adapter；验证完整 Items/Attributes 和 item detail；修 Price Check drift；保留 rate/version/build/patch headers；统一百分比；刷新中英目录。

验收：build 0.17.151.9472 / patch 132 的 live 脱敏夹具通过；不含 key/player；rarity comma 回归先红后绿；所有 UI 选项来自目录/facets；中英 key 与规范 ID 覆盖门禁通过。

M2 · SearchSpec 与 query planner

工作：新 SearchSpec、目录 resolver、语义安全 server/local planner、全局预算与 round-robin、取消、限流、缓存、确定性合并。

验收：AND/OR/K 纯函数测试通过；多名称/多品质正确拆请求；K<N 不变成服务端 AND；旧请求不能发布；每族 count/completeness 精确。

M3 · 筛选 UI

工作：响应式布局、规范可搜索多选、词条规则编辑器与 K、draft/Search/Apply locally/Reset、active chips 与无障碍。

验收：中英文下全部键盘可用；切语言保持选择；无硬编码选项/结果；无效范围不发请求；窄屏无 shell 横向溢出。

M4 · 结果与状态 UX

工作：桌面表格/窄屏卡片、展开详情、count/completeness/freshness、所有 loading/empty/stale/incomplete/rate/auth/partial/fatal 状态，以及可复制的游戏内手动搜索摘要。

验收：每种状态有 fixture-driven 覆盖；stale empty 不声称权威空；incomplete 始终显示 retrieved/reported；合并顺序确定；堆叠标清总价/单位价；结果行与展开操作都不调用 Price Check。

M5 · live 只读验收

工作：代表性 DarkerDB 搜索；可选短时被动 Marketplace request capture；绝不上架。

验收：覆盖单名多品质、多名、职业/类别/栏位、K=N、K<N、stale 与主动 incomplete；UI count 与 adapter diagnostics 一致；不加入任何游戏输入或 listing automation。

自动上架继续保留为后续独立阶段，并继续受既定人工检查点约束。
